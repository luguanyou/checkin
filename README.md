# 智能课堂考勤

前端采用 React、TypeScript 和 Vite，业务数据来自 `api/` 下的 FastAPI 服务。教师端覆盖登录、首次修改密码、工作台、课程班级、学生名单导入、课堂点名、考勤修正、平时成绩及 CSV/XLSX 导出；超级管理员登录后进入独立的教师账号管理页面。

## 使用文档

- [管理员与教师使用教程](docs/admin-teacher-user-guide.md)：覆盖角色权限、教师账号管理、课程班级、名单导入、课堂点名、记录修正、导出与常见问题。

## 本地开发

Windows 用户安装并启动 Docker Desktop、[uv](https://docs.astral.sh/uv/) 和 Node.js 后，可以双击根目录的 `start.bat`。脚本会自动启动持久化的开发 MySQL、安装或同步依赖、执行数据库迁移，并在独立窗口启动 API 和前端，服务就绪后会打开浏览器。

首次启动会自动创建 `api/.env`，并在启动窗口显示随机生成的本地管理员密码；凭据也会保存在该文件中。后续启动会保留已有配置和数据库数据，不会覆盖 `api/.env`。

以下命令用于手动启动或排查问题。

安装前端依赖：

```powershell
npm install
```

复制前端环境配置并按需修改 API 地址：

```powershell
Copy-Item .env.example .env.local
```

按 [API README](api/README.md) 启动 MySQL、执行迁移并配置超级管理员。用于普通 HTTP 本地开发的 `api/.env` 需要包含：

```dotenv
FRONTEND_ORIGIN=http://127.0.0.1:5173
REFRESH_COOKIE_SECURE=false
ADMIN_USERNAME=admin
ADMIN_DISPLAY_NAME=超级管理员
ADMIN_PASSWORD=请替换为至少12位的安全密码
```

API 启动时会根据这些配置自动创建或同步超级管理员，不需要运行账号创建命令。修改 `ADMIN_PASSWORD` 并重启 API 可以重置密码；真实 `.env` 包含明文凭据，必须限制文件权限且不得提交。

启动 API：

```powershell
Set-Location api
uv run uvicorn attendance_api.main:app --host 127.0.0.1 --port 8000 --reload --reload-dir src
```

另开终端启动前端：

```powershell
npm run dev
```

访问 `http://127.0.0.1:5173`。Vite 会把 `/api` 转发到 `VITE_API_PROXY_TARGET`，默认是 `http://127.0.0.1:8000`。

## 教师账号管理

使用 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD` 登录后，系统进入 `/admin` 教师账号工作台。管理员可以搜索和筛选教师账号，并执行创建、停用、启用和重置密码。

创建或重置成功后，临时密码只显示一次。请立即使用“复制登录凭据”保存并通过可信渠道交给教师；关闭对话框后无法找回，只能再次重置。教师使用临时密码登录后必须先设置自己的新密码。

开发数据库使用本机端口 `33306`，测试数据库使用独立端口 `33307`，两者可以同时运行。启动并迁移测试数据库：

```powershell
Set-Location api
docker compose -f compose.test.yaml up -d --wait
uv run --env-file .env.test.example alembic upgrade head
uv run --env-file .env.test.example pytest
```

## 学生注册审核

学生账号全局唯一。同一学生在多位老师的有效班级名单中时，各位任课老师都可以从自己的“学生名单 → 学生注册审核”查看并处理其注册申请，无论学生提交申请时选择的是哪位老师的课程班级。任意老师处理后，其他老师看到的申请状态和审核历史同步更新，重复审核会提示刷新。

共享依据是学号对应的学生 ID 与有效名单关系，不按班级名称合并。仅有相同班级名称、尚未将学生加入自己名单的老师不会看到这些申请；已移除的学生不会继续出现在其他课程的共享列表中。原提交班级仍保留申请记录，审批通过时必须核对当前名单。班长的审核授权仍限于原授权班级提交的申请。

此次调整无需数据库迁移，更新并重启后端即可生效，已有待审核申请自动按上述规则显示。

## 平时成绩

教师可从导航或课程班级进入“平时成绩”。按班级建立作业、课堂表现、上机实验表现及其他项目，录入正负小数积分并保留备注和变更记录。每个项目可配置默认积分，用于初始化学生分值；项目默认值后续可编辑，但不会覆盖学生已保存的单独分值。班级基础分默认显示 70，可自行配置；每类独立配置“1 积分折合多少分”，不设类别积分或加扣分上限。

`原始总分 = 基础分 + Σ（类别净积分 × 类别系数）`；最终成绩限制为 0～100，并保留原始总分。规则可稍后设置，空值与零积分分别处理。考勤不参与平时成绩，期末成绩及课程总评不在本模块范围内。

升级已有环境需先在 `api/` 运行 `uv run alembic upgrade head`，新增成绩表；然后重启后端并重新构建前端。`start.bat` 会执行迁移。迁移前请按现有运维流程备份数据库。

## 验证与构建

```powershell
npm run typecheck
npm run test:unit
npm run build
npm run test:browser
```

浏览器测试会自行启动临时 Vite 服务并使用确定性的 API 契约夹具，不要求本地 API 或 MySQL 正在运行。后端验证命令见 [API README](api/README.md)。

生产构建输出在 `dist/`。生产环境应从同一个 HTTPS 站点提供 `dist/` 和 `/api`，或通过等价的反向代理保持同源，并设置：

```dotenv
REFRESH_COOKIE_SECURE=true
FRONTEND_ORIGIN=https://attendance.example.edu
```

访问令牌仅保存在浏览器内存中；刷新令牌由后端通过 HttpOnly Cookie 管理。

## 学生个人查询与查看权限

教师在“学生名单 → 学生查看设置”中按班级控制开放范围：考勤可关闭或开放本人记录；平时分可关闭、仅开放总分、开放总分及明细。新旧班级升级后默认关闭，关闭的内容由后端直接过滤。已被学生查看或保存的信息无法收回。

在学生行点击“开通学生账号”，设置 12～128 位初始密码，并单独告知学生。学生使用学号和密码登录，首次必须修改密码，随后自动进入个人中心。账号与学生身份绑定，可查看本人仍在名单中的班级，不允许录入分数、管理项目、查看他人记录。同一学生跨班级复用账号，无需重复开通。管理员可切换“账号类型”为“学生账号”，停用或重置密码。

总分是随教师录入变化的当前计算结果，不代表最终确认；尚未评价的项目明确标识。学生页面会定期刷新，也可手动刷新。

本功能需要数据库迁移 `0006`。在 `api/` 目录执行 `uv run alembic upgrade head`，然后重启后端并构建前端；现有启动脚本同样会执行迁移。回退此迁移前必须先处理学生账号。

新增权限与数据隔离测试可在仓库根目录运行：`api/.venv/Scripts/python.exe -m pytest api/tests/test_portal.py -q -p no:cacheprovider`。该组使用 SQLite 验证接口与服务逻辑，真实 MySQL 迁移仍需在对应环境执行。

## 课程资料与作业

教师从「课程班级 → 教学内容」发布资料。资料可填写章节和学习说明，选择「课堂资料」或「自主学习」，并添加链接或附件。发布时默认选择当前班，可增选本课程的其他班级。修改共用资料后，所选班级会看到更新。取消勾选某班只撤回该班的发布，使用「撤回」会移除所有班级的发布。

作业按当前班级发布，须填写作业要求、截止时间和提交方式，可附上模板或引用已向本班发布的资料。截止时间以浏览器本地时区输入和显示。学生在「我的课程」切换班级，查看临近截止的作业和按章节整理的资料。

系统会在读取资料和下载附件时校验当前名单及发布范围。每条内容可附一个最大 10 MB 的文件，附件随数据库保存。启用前需升级到迁移 `0009`，现有启动脚本会执行迁移。

## 班长项目代录

老师在“学生名单 → 班长授权管理”中选择学生，勾选允许代录的项目并保存。尚无账号可在该弹窗中先开通学生账号，已有账号跨班级复用。可给多名班长分配不同项目；取消部分勾选可缩小权限，“撤销全部授权”可取消该账号在本班的全部代录权限。账号整体停用或密码重置仍由管理员处理，老师的授权只影响本人课程班级。

获授权的学生登录后，从对应班级的“班长登记授权项目”进入代录页面。只能查看授权项目的名单、积分和备注，不能查询其他项目成绩、汇总成绩、其他人的考勤，也不能创建或修改项目、规则和名单。班长本人的积分只读，由任课老师登记。所有代录修改写入现有成绩审计记录，老师可在“变更历史”查看实际操作人及修改前后的值。

学生本人数据查看开关和班长代录授权独立。项目按班级授权，新增项目默认不授权。移出名单、停用账号、归档课程或班级时代录权限不可使用；恢复状态后已有授权可继续使用，永久取消请撤销授权。撤销后后端立即拒绝新的读取和保存请求，此前已查看的信息无法收回。老师和班长同时修改时沿用成绩版本校验，冲突会保留班长草稿，需刷新核对后重新录入。

本功能需要迁移 `0007`：在 `api/` 目录运行 `uv run alembic upgrade head` 后重启后端。新增权限测试：`api/.venv/Scripts/python.exe -m pytest api/tests/test_monitors.py api/tests/test_portal.py -q -p no:cacheprovider`。

## 名单编辑

教师在学生名单每行点击“编辑”，可修改学号、姓名、性别、专业，采用与新增学生一致的弹窗布局。学号与姓名必填，重复学号或登录账号冲突会拒绝保存并保留输入。归档班级、课程不可编辑，班长及普通学生无名单编辑权限。

学生基础资料跨班级共用，修改会同步到该学生所在的其他班级；已有考勤快照与成绩关联保持不变。学生已开通账号时，修改学号会同步登录用户名，修改姓名会同步账号显示名称，密码保持原值。修改学号后请告知学生使用新的学号登录。

此功能复用现有学生数据表，无新增数据库迁移。相关后端验证：`api/.venv/Scripts/python.exe -m pytest api/tests/test_roster_edit.py -q -p no:cacheprovider`。

## 学生自助注册与审核

学生可从登录页进入“学生注册”（`/register`），填写名单中的学号、姓名，匹配并选择有效班级，自行设置密码后提交申请。待审核时不可登录；输入正确密码尝试登录可查看待审核或驳回提示。驳回后可重新申请，新的申请使用新标识，防止旧审核页面误处理。已有账号不能通过重新注册覆盖密码或解除停用。

老师在“学生名单 → 学生注册审核”处理本班申请，支持单条、批量通过或驳回，每批最多 100 条；可填写原因并查看审核历史。通过后才创建学生账号，使用学生自行设置的密码，无需老师发送初始密码。审核确认的是统一学生身份，账号可查看本人各班级已开放的数据。

老师在“班长授权管理”中可独立勾选“允许审核本班学生注册”，无需同时授予成绩项目权限。获授权班长登录个人中心后，可从对应班级的“审核本班学生注册”进入审核页面。班长不能自审、不能审批其他班级、不能转授权限；移出名单、停用账号、归档班级或撤销授权后不可审核。审核人、时间、结果和原因保留在历史及审计日志中，审核人员不能查看学生密码。

本功能需要数据库迁移 `0008`，新建注册申请和审核授权表。在其他环境启用时，先在 `api/` 目录运行 `uv run alembic upgrade head` 后重启后端。本地开发环境已应用此迁移。验证命令：`api/.venv/Scripts/python.exe -m pytest api/tests/test_registrations.py api/tests/test_monitors.py api/tests/test_portal.py api/tests/test_roster_edit.py -q -p no:cacheprovider`。
