场次表：保存“哪一次”

字段类型用途
idINT 主键自增内部场次标识
session_dateDATE 非空点名日期
titleVARCHAR(50) 非空例如上午第1次点名
CREATE TABLE attendance_sessions (
  id INT PRIMARY KEY AUTO_INCREMENT,
  session_date DATE NOT NULL,
  title VARCHAR(50) NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
教师备注 · 备课与面试延伸同一天可有多次点名，不对session_date单独设置UNIQUE。title是教学简化字段，真实项目包含class_group_id、状态、开始完成时间等。

LESSON 04 / 认识与理解

记录表：保存“谁在这次怎么样”

字段类型用途
idINT 主键自增记录标识
session_idINT 非空，外键属于哪次点名
student_idINT 非空，外键是哪名学生
statusVARCHAR(10)，默认pending这次点名的结果

pending 待点名 · present 出勤 · absent 缺勤 · leave 请假 · late 迟到

教师备注 · 备课与面试延伸本教学DDL暂不加CHECK，状态仍可写入其他字符串，必须明确这一限制；真实项目通过CHECK与接口校验约束状态。默认值不等于合法值列表。

LESSON 04 / 教师演示

两个外键，加一条不重复规则

CREATE TABLE attendance_records (
  id INT PRIMARY KEY AUTO_INCREMENT,
  session_id INT NOT NULL,
  student_id INT NOT NULL,
  status VARCHAR(10) NOT NULL DEFAULT 'pending',
  UNIQUE (session_id, student_id),
  FOREIGN KEY (session_id)
    REFERENCES attendance_sessions(id),
  FOREIGN KEY (student_id) REFERENCES students(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

UNIQUE(session_id, student_id)：同一次点名，同一个学生最多一条记录。

教师备注 · 备课与面试延伸SQL较长：先讲两条FOREIGN KEY再讲UNIQUE，强调联合唯一不是每列单独唯一。使用InnoDB；不添加级联删除，不关闭外键检查。

为什么不把今天的状态直接放在students中？

因为状态属于“学生在某次点名中的结果”。只放一个状态会覆盖历史，无法同时表达不同日期的结果。
