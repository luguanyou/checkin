LESSON 03 / 认识与理解

查看全部，再选择需要的列

SELECT * FROM students;

SELECT student_number, name
FROM students
ORDER BY student_number;
  • 星号 * 表示所有列。
  • 明确列名，可以只取需要的数据。
  • 需要稳定顺序时，写出 ORDER BY。
教师备注 · 备课与面试延伸不写ORDER BY不能保证展示顺序。SELECT只读数据，不会新增记录。SELECT *适合此处观察，实际接口应按需要选择字段。

student_numbername

LESSON 03 / 认识与理解

名字里有“晨”的学生怎么找

SELECT student_number, name
FROM students
WHERE name LIKE '%晨%';
01

%

匹配任意长度的字符。

02

'%晨%'

查找姓名中包含“晨”的学生。

精确匹配用 =；本页用 LIKE 做包含查找。

教师备注 · 备课与面试延伸LIKE作为挑战示范，若学生主线未掌握可以略过。教师进阶：前置通配符查询通常不适合普通B-tree索引定位；此处不讲优化。

LESSON 03 / 教师演示

更正姓名：先查，再改，再查

-- 1. 先确认目标
SELECT * FROM students WHERE student_number = '003';
-- 2. 更正王浩的姓名
UPDATE students SET name = '王昊'
WHERE student_number = '003';
-- 3. 检查结果
SELECT * FROM students WHERE student_number = '003';

预期：003变为王昊，其余学生保持原值。

教师备注 · 备课与面试延伸练习使用虚构改名场景。提醒WHERE唯一定位；在自动提交开启时执行后就会保存，本节不承诺可随意撤销，事务在后续课讲。

LESSON 03 / 认识与理解

如果数据库拒绝了你的操作

现象可能原因检查办法
Duplicate entry学号重复查询该学号是否已存在
Column cannot be null必填字段被设为NULL核对输入和值
查询不到结果条件不匹配或选错库检查学号、引号、当前库
修改影响0行未匹配或值原本相同执行SELECT确认结果

报错是线索。先看具体提示，再核对 SQL。

教师备注 · 备课与面试延伸影响行数可能按客户端配置表示匹配或改变，不能仅靠0行判断是否失败。唯一约束错误也可能来自其他唯一字段，检查具体报错。
