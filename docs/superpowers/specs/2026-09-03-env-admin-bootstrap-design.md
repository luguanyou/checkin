# 超级管理员环境变量初始化设计

## 目标

通过 API 的 `.env` 配置自动创建或同步指定的超级管理员账号，取消依赖命令行初始化。管理员登录后进入简单的专属页面，不访问仅限教师的课程和考勤接口。

## 配置

后端新增三个可选配置项：

```dotenv
ADMIN_USERNAME=admin
ADMIN_DISPLAY_NAME=超级管理员
ADMIN_PASSWORD=至少12位的密码
```

`ADMIN_PASSWORD` 未配置或为空时，不执行管理员初始化。用户名和显示名称提供上述默认值。示例环境文件只提供占位说明，不包含可用密码。

## 启动同步

数据库迁移仍由部署流程先行执行。API 启动时，在开始接受请求前执行一次管理员同步：

1. 规范化用户名和显示名称，并验证密码长度为 12 至 128 个字符。
2. 用户名不存在时，创建 `ADMIN`、`ACTIVE`、`must_change_password=false` 的账号，只保存 Argon2id 哈希。
3. 用户名已存在且角色为 `ADMIN` 时，同步显示名称和启用状态。仅当配置密码与现有哈希不匹配时更新密码哈希，并撤销该账号的全部有效刷新会话。
4. 用户名已由 `TEACHER` 占用时启动失败，错误明确指出配置冲突，不改变现有用户。
5. 配置密码不符合策略或数据库尚未迁移时启动失败，不以半初始化状态提供服务。

因此 `.env` 是超级管理员凭据的来源。修改 `ADMIN_PASSWORD` 并重启 API 即可重置密码；未修改配置的普通重启不会重哈希密码或撤销会话。

## 登录行为

登录是凭据验证，不应用新密码强度规则。后端登录请求接受 1 至 128 个字符的密码，前端登录表单只校验用户名和密码非空。创建、同步和修改新密码时仍执行 12 至 128 个字符的策略。

这使已有短密码账号可以完成登录，同时不降低新密码要求。用户名继续在服务端去除首尾空白并转为小写。

## 管理员页面与路由

认证成功后按角色跳转：

- `ADMIN` 进入 `/admin`。
- `TEACHER` 进入现有 `/` 教师工作台。

`/admin` 只显示当前管理员的显示名称、用户名、管理员身份和退出操作，不请求教师业务接口。角色路由同时阻止管理员进入教师页面、教师进入管理员页面。首次改密路由的现有行为保持不变。

## 错误与安全

- `.env` 不纳入版本控制，部署方必须限制文件读取权限。
- 日志不得输出 `ADMIN_PASSWORD`、密码哈希或令牌。
- 启动日志只记录管理员已创建、已同步或无需变更，并可记录非敏感用户名。
- 密码同步与会话撤销在同一数据库事务中完成。
- 自动同步只管理配置用户名对应的管理员，不删除其他历史管理员账号。

## 测试

后端覆盖：未配置时不创建、首次创建、重复启动幂等、密码变化时更新并撤销会话、教师用户名冲突、非法密码拒绝启动，以及短旧密码可以进入登录验证。

前端覆盖：登录表单允许提交非空短密码；管理员登录后跳转 `/admin`；管理员页不发起教师业务请求；教师和管理员的角色路由互相隔离；退出登录正常工作。
