# 教师账号管理工作台设计

## 目标与范围

将现有仅展示管理员身份的 `/admin` 页面升级为教师账号管理工作台，使超级管理员可以查询、创建、启用、停用和重置教师账号密码。

本次仅补齐前端能力，复用现有 `/api/v1/admin/users` 接口、认证与权限校验、用户表和审计日志，不修改后端或数据库。管理员不通过该页面访问教师的课程、班级、名单和考勤数据，也不增加教师自行注册、删除账号、批量导入或多级管理员权限。

## 页面结构

继续使用单一路由 `/admin`，保持现有深绿色顶部栏、管理员身份和退出操作。主体采用紧凑单页管理台：

1. 页面标题区展示“教师账号”、账号摘要和“创建教师”主操作。
2. 摘要展示教师账号总数、启用数和停用数。
3. 工具栏支持按姓名或用户名搜索、按启用状态筛选。
4. 桌面端用表格展示姓名、用户名、账号状态、首次改密状态、最近登录时间和行操作。
5. 移动端将同一数据转换为纵向列表，行操作收进每个账号的操作菜单，避免横向溢出。
6. 列表支持分页，并为加载、空数据、失败和重试提供明确状态。

账号列表请求固定携带 `role=TEACHER`，不会显示管理员账号。搜索、状态和页码保存在 URL 查询参数中。账号总数、启用数和停用数分别通过不带状态、携带 `status=ACTIVE`、携带 `status=DISABLED` 且 `page_size=1` 的三个独立列表请求获取 `total`，统计值不受当前搜索、筛选和页码影响。

## 账号操作

### 创建教师

“创建教师”打开对话框，管理员填写教师姓名和用户名。用户名与后端一致，在提交时去除首尾空格并转为小写；姓名去除首尾空格。前端在打开表单时使用 `crypto.getRandomValues` 从排除易混淆字符的字母和数字集合生成 16 位临时密码，满足后端 12 至 128 位策略。

创建请求发送 `username`、`display_name` 和 `temporary_password`。请求成功后关闭表单并打开一次性凭据结果对话框，显示姓名、用户名和临时密码，提供复制凭据按钮。教师账号初始状态为启用，且首次登录必须修改密码。

结果对话框关闭后清除临时密码；页面刷新也无法恢复。若管理员未及时保存凭据，只能通过重置密码生成新的临时密码。

### 启用与停用

启用或停用通过行操作发起。停用前显示确认对话框，明确说明教师将无法登录且现有登录会话会被撤销。重新启用也要求确认，但不生成新密码；教师使用原密码登录。成功后刷新列表及统计数据并显示成功提示。

### 重置密码

重置密码操作先显示确认和影响说明。确认后由浏览器重新生成 16 位临时密码并提交；成功后显示一次性凭据结果对话框。重置会撤销该教师现有登录会话，并要求其下次登录后修改密码。关闭结果对话框后清除临时密码。

## 前端架构与数据流

在现有 API 类型中补充管理员用户分页及请求输入类型，在 `createApi` 中增加：

- `adminUsers.list(params)`：分页、角色、状态和关键词查询。
- `adminUsers.create(input)`：创建教师账号。
- `adminUsers.updateStatus(userId, status)`：启用或停用。
- `adminUsers.resetPassword(userId, temporaryPassword)`：重置临时密码。

`AdminPage` 负责页面编排、URL 参数和 React Query 查询。创建、凭据结果、状态确认和密码重置分别使用小型组件，并复用现有 `Dialog`、`Pagination`、异步状态和 Toast 组件。所有成功 mutation 都使教师列表与统计查询失效并重新获取；提交期间禁用相关按钮，防止重复请求。

不将临时密码写入 URL、浏览器存储、日志或 React Query 缓存。密码只存在于当前表单或一次性结果对话框的 React 本地状态中，并在关闭时清除。复制操作使用 Clipboard API；复制失败时保留可选择的明文字段并显示错误提示。

## 校验与错误处理

- 姓名和用户名不能为空；用户名最长 64 个字符，姓名最长 100 个字符，与 API 约束一致。
- 生成的临时密码固定为 16 位，创建和重置不提供手动编辑入口。
- 后端返回重复用户名或其他业务错误时，在当前对话框内展示后端消息，并保留姓名和用户名。
- 列表请求失败时展示错误状态和重试按钮；统计请求单独失败时显示占位符，不阻止账号列表使用。
- mutation 失败时不更新本地账号状态，以服务端响应为准。
- 认证失效继续由现有 API 客户端统一刷新会话或退出登录。

## 可访问性与响应式

所有对话框沿用现有焦点管理和 Escape 关闭行为。输入框使用可见标签，状态同时用文字和颜色表达，图标按钮带可访问名称和提示。复制结果通过 Toast 的 `aria-live` 区域反馈。桌面和移动布局均保持至少 44 像素的主要点击目标，并支持 320 像素宽屏幕和减少动画偏好。

## 测试与验收

前端单元和组件测试覆盖：

- 管理员列表固定发送 `role=TEACHER`，并正确映射搜索、状态和分页参数。
- 总数、启用数和停用数来自对应查询的 `total`。
- 临时密码生成长度、字符集合和随机源。
- 创建成功、一次性凭据展示、复制和关闭后清除。
- 重复用户名等服务端错误保留表单内容。
- 停用、启用和重置密码的确认、请求参数、会话影响说明及查询刷新。
- 加载、空数据、失败重试和分页状态。
- 只有管理员可访问 `/admin`，现有教师角色路由不回归。

浏览器测试补充管理员登录后创建教师、复制一次性凭据、停用、启用和重置密码的主流程，并在桌面与移动视口检查无横向溢出、不可见操作或页面错误。

完成标准为 TypeScript 类型检查、单元测试、生产构建和浏览器测试全部通过，且现有后端测试保持通过。
