# 智能课堂考勤 React 前端设计

## 1. 目标

将现有原生 HTML/JavaScript 高保真原型重写为连接真实 FastAPI 服务的 React 单页应用。保留已验证的“清朗教务”视觉方向和教师工作流，补齐登录、首次修改密码、真实课程与名单、名单导入、课堂点名、记录修正、文件导出以及完整的加载和错误状态。

本次交付面向教师角色。管理员教师账号管理不在本次前端范围内，但后端现有管理员接口保持不变。

## 2. 技术选型

- React、TypeScript 和 Vite负责应用构建与开发服务器。
- React Router负责页面路由、受保护路由和登录重定向。
- TanStack Query负责服务端数据缓存、分页、请求去重、更新后失效和有限重试。
- Lucide React提供统一的线性图标。
- 原生 CSS负责设计令牌、布局、响应式和交互状态，不引入组件样式框架。
- Vitest与Testing Library负责单元和组件测试；Playwright负责浏览器工作流和响应式验证。

## 3. 路由与页面

| 路由 | 页面 | 主要职责 |
| --- | --- | --- |
| `/login` | 登录 | 用户名和密码登录、服务不可用提示 |
| `/change-password` | 首次修改密码 | 阻止未改初始密码的用户进入业务页面 |
| `/` | 工作台 | 从课程和近期场次派生今日任务与概况 |
| `/courses` | 课程班级 | 查询、新建、编辑和归档课程与班级 |
| `/classes/:classId/roster` | 学生名单 | 搜索、分页、移除/恢复成员、模板下载和导入 |
| `/attendance/:sessionId` | 课堂点名 | 加载场次、快捷标记、语音、同步和完成场次 |
| `/records` | 考勤记录 | 按课程、班级、日期与状态筛选场次 |
| `/records/:sessionId` | 场次详情 | 查看记录、填写原因修正已完成记录并导出 |

未知路由显示应用内 404 页面。未登录访问业务页面时跳转至 `/login`；登录后返回原目标页面。`must_change_password` 为真时只能访问修改密码和退出登录。

## 4. 前端结构

```text
src/
  api/             请求客户端、契约类型和各资源 API
  app/             路由、QueryClient、认证上下文和全局入口
  components/      按钮、字段、对话框、Toast、分页和状态视图
  features/
    auth/
    dashboard/
    courses/
    roster/
    attendance/
    records/
  hooks/           语音、媒体查询和焦点管理
  styles/          设计令牌、基础样式、布局和组件样式
  test/            测试初始化与 API 测试工具
```

功能目录只依赖共享组件和 `api` 层，不直接拼接请求地址。API 响应使用与后端一致的 snake_case 类型，避免在多个页面重复转换；仅在展示选择器中生成视图模型。

## 5. 认证与请求生命周期

访问令牌只保存在运行时内存，不写入 `localStorage` 或 `sessionStorage`。刷新令牌继续由后端通过 HttpOnly Cookie 管理。

1. 应用启动后调用 `/auth/refresh` 尝试恢复会话。
2. 恢复成功后保存新的访问令牌和用户信息，再渲染受保护页面。
3. 普通 API 返回 401 时，请求客户端只触发一次共享刷新，避免多个并发请求重复刷新。
4. 刷新成功后原请求重试一次；再次失败则清空内存认证状态并跳转登录页。
5. 退出登录调用后端接口，并在成功或失败后清除本地内存状态和Query缓存。

所有认证请求使用 `credentials: include`。开发环境通过 Vite 将 `/api` 代理到 FastAPI，生产环境要求反向代理让页面与 `/api` 同源。后端增加 `refresh_cookie_secure` 配置：生产默认开启，本地 HTTP 开发显式关闭。

## 6. 服务端状态与数据流

TanStack Query键按资源和查询条件组织，例如课程列表、班级名单、场次列表和场次详情。筛选条件进入 URL 查询参数，使刷新和浏览器前进/后退可恢复当前视图。

- 工作台并行请求活动课程和近期场次，在前端计算课程数、待完成场次和到课率。
- 课程创建或更新成功后失效课程列表；班级创建或更新同时失效所属课程。
- 名单搜索与分页由后端完成。导入确认成功后失效当前名单和课程统计。
- 创建点名场次成功后直接导航到后端返回的场次 ID；同一班级同一天的每次创建都生成独立场次。
- 记录修正成功后同时更新场次详情缓存并失效场次列表。

页面不使用示例数据作为静默降级。服务不可用时显示明确错误和重试操作，避免把模拟结果误认为真实数据。

## 7. 点名交互与并发

点名页以服务器返回的 DRAFT 场次和记录为唯一事实来源。当前学生索引是页面本地状态，可从第一个 `pending` 记录初始化。

- `Space`、`1`、`2`、`3`分别标记已到、缺勤、请假和迟到；`Backspace`回到上一位；`R`重新播报；`M`切换静音。
- 输入框、选择器或对话框获得焦点时，全局快捷键停用。
- 状态点击后立即在界面更新，并异步发送 `status`、`expected_version` 和 `client_mutation_id`。
- 同一记录的连续修改按顺序提交；其他记录可以并行提交。
- 成功响应中的新 `version` 覆盖缓存版本。
- 网络失败时回滚该记录并提供重试；409并发冲突时重新加载场次，提示数据已被其他窗口修改。
- 仍有 `pending`、失败请求或正在提交的请求时禁止完成场次。
- 完成成功后替换场次状态并跳转场次详情。

Web Speech API不可用时显示一次非阻塞提示，键盘和按钮流程保持可用。

## 8. 名单导入与文件导出

名单导入对话框使用真实文件控件并限制后端支持的扩展名与10 MiB大小。选择文件后上传到预览接口，显示总数、有效行、错误、重复和可导入数量。存在错误时禁止确认；重复数据由教师选择“跳过”或“恢复已有关系”。预览过期时返回文件选择步骤并保留错误说明。

模板下载由前端生成UTF-8 BOM CSV模板。考勤导出调用后端二进制接口，从 `Content-Disposition`解析文件名并通过临时对象URL触发下载，完成后立即释放URL。

## 9. 视觉、响应式与可访问性

沿用现有深绿导航、白色工作表面和琥珀主操作色。状态颜色继续同时配套图标与文字。桌面端使用侧边导航，768像素以下切换顶部栏和底部导航；点名页在所有尺寸保持无干扰任务布局。

- 所有表单字段有持久标签和就地错误信息。
- 图标按钮提供可访问名称和工具提示。
- 对话框打开时移动焦点、限制焦点范围，关闭后归还触发元素。
- 页面请求时保留稳定布局并使用骨架或明确加载状态。
- 触控目标不小于44像素，支持键盘操作和 `prefers-reduced-motion`。
- 320像素宽度不产生页面级横向滚动；宽表格在自身容器内滚动。

## 10. 错误处理

API客户端把后端统一错误转换为包含 `status`、`code`、`message`、`details` 和 `requestId` 的错误对象。字段校验错误显示在对应字段；认证、权限、资源不存在、冲突、限流和服务错误分别提供可执行反馈。未知错误展示请求ID，便于服务端排查。

查询错误显示页面级重试；变更错误保留用户已输入内容。Toast只用于操作结果，不承载必须持续阅读的错误。危险操作和不可逆状态迁移使用确认对话框。

## 11. 测试策略

- API客户端：请求头、Cookie、共享刷新、一次重试、错误转换、上传和下载文件名。
- 认证：启动恢复、登录、强制修改密码、退出和受保护路由。
- 业务组件：课程表单、名单分页与搜索、导入校验、场次筛选和修正原因。
- 点名：快捷键排除、索引边界、乐观更新、版本递增、失败回滚、冲突刷新和完成阻塞。
- 浏览器流程：登录、创建课程班级、导入名单、创建场次、完成点名、修正和导出。
- 视觉验收：1440、390和320像素视口，无页面横向溢出、无控制台错误，关键页面截图人工检查。

浏览器测试使用可控的API替身覆盖前端边界；另运行后端现有测试保证契约。若本地MySQL可用，再执行一条真实前后端集成冒烟流程。

## 12. 完成标准

- 页面不再依赖硬编码业务样例完成正常流程。
- 教师可从登录开始完成课程、班级、名单导入、点名、修正和导出。
- 认证刷新、API失败、并发冲突和空数据均有明确且可恢复的界面状态。
- 单元、组件和浏览器测试全部通过，后端测试不因开发Cookie配置而回归。
- 开发命令和环境变量记录在项目README中。
